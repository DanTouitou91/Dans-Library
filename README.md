# אוסף ספרי הלמידה של דן

ספרייה דיגיטלית בעיצוב וינטג' לחומרי הלמידה של דן טואיטו.
אתר סטטי לחלוטין (HTML + CSS + JavaScript), ללא שלב בנייה וללא שרת.

---

## ✦ איך מוסיפים ספר חדש

שלושה שלבים:

**1. העלו את קובץ ה-PDF לתיקייה `books/`**

```
books/mikro-kalkala.pdf
```

**2. הוסיפו רשומה למערך `CATALOG` שבראש הקובץ `script.js`**

המערך הוא הדבר הראשון בקובץ, מתחת לכותרת `§0` — אין צורך לגלול לתוך הקוד.

```js
{
  // ⚠️ המזהה קבוע לנצח. שינוי שלו ימחק את ההערות והסימניות של הספר.
  //    באנגלית בלבד — לעולם לא בעברית.
  id: 'mikro-kalkala',

  title: 'מבוא למיקרו-כלכלה',            // מוטבע על שדרת הספר ובכותרת הכרטיסייה
  file: 'books/mikro-kalkala.pdf',        // נתיב יחסי, או כתובת URL מלאה

  sources: [                              // מוצג ברשימה בכרטיסיית הקטלוג
    'ספר הקורס, האוניברסיטה הפתוחה',
    'מקבץ מאמרי חובה, יחידות 1–6',
  ],

  shelf: 'שנה ב׳',                        // רשות — שם המדף. ברירת מחדל: 'הקורסים שלי'
  spine: { color: '#1F3D2B', height: 0.98 }, // רשות — צבע בד הכריכה וגובה יחסי (0.8–1.05)
  note: 'עודכן בסמסטר ב׳',                // רשות — שורת מידע בתחתית הכרטיסייה
},
```

**3. בצעו commit ו-push**

```bash
git add books/mikro-kalkala.pdf script.js
git commit -m "הוספת ספר: מבוא למיקרו-כלכלה"
git push
```

Netlify מזהה את השינוי ומפרסם אותו אוטומטית תוך פחות מדקה.

### טיפים

| רוצה… | עשה |
|---|---|
| מדף נוסף | תן ל-`shelf` שם חדש. כל שם יוצר מדף עץ נפרד. |
| ספרים בגבהים שונים | שנה את `spine.height` בין 0.8 ל-1.05 — המדף נראה טבעי יותר. |
| להסיר ספר | מחק את הרשומה מהמערך (ההערות שלו יישמרו אם תחזיר אותה עם אותו `id`). |
| ספר נשאר שבור אחרי שהעליתי אותו | העלה את `rev` ב-1. זה יוצר כתובת חדשה ועוקף עותק תקוע במטמון. |
| לשנות שם קורס | שנה רק את `title`. **אל תיגע ב-`id`.** |
| לעדכן מהדורה של ספר | דרוס את קובץ ה-PDF **באותו שם קובץ** והשאר את ה-`id` כפי שהוא. |

### החלפת מהדורה לספר קיים

כשיוצאת מהדורה חדשה לספר שכבר באתר, פשוט דרסו את ה-PDF הקיים תחת אותו
שם קובץ ואל תיגעו ב-`id`. כך ההערות בפנקס המלומד נשמרות.
שתי נקודות שכדאי לדעת:

- **מספרי העמודים מתייחסים לקובץ, לא לתוכן.** אם המהדורה החדשה ארוכה
  או קצרה יותר, הסימניות הישנות יצביעו לעמודים אחרים. ההערות עצמן
  אינן קשורות לעמוד ולכן נשארות שלמות.
- **אם המהדורה החדשה קצרה יותר** מהעמוד האחרון שנקרא, האתר פותח את
  העמוד האחרון הקיים במקום ליפול — הערך נחתך לטווח התקין
  (`clamp`, ב-`script.js`).

## ✦ אוסף קלטות הוידאו של דן — הסרטונים

עמוד נפרד (`videos.html`) בסגנון חנות וידאו של שנות ה-90: מדף קלטות,
הכנסת הקלטת למכשיר, טלוויזיה, פרקים, מסך מלא והמשך צפייה. הכפתור
"קלטות הוידאו" בראש הספרייה מוביל אליו.

### איך מוסיפים סרטון

1. **מעלים את הקובץ ל-Release**, לא למאגר:
   [עמוד ה-Release](https://github.com/DanTouitou91/Dans-Library/releases/tag/videos-v1)
   → העיפרון (Edit) → גוררים את ה-MP4 לתיבת הקבצים → מחכים שהפס יסתיים
   → **Update release**. שם קובץ באנגלית ובלי רווחים.
2. **שולפים את הפרקים המוטמעים** (הדפדפן לא יודע לקרוא אותם בעצמו):
   ```bash
   pip install imageio-ffmpeg
   python3 tools/chapters.py https://github.com/DanTouitou91/Dans-Library/releases/download/videos-v1/<שם-הקובץ>.mp4
   ```
   הסקריפט קורא רק את הכותרת של הקובץ (בקשות Range — לא 250MB), מדפיס
   את `duration` ואת `chapters`, ומזהיר אם הקובץ יתחיל להתנגן לאט.
3. **מוסיפים רשומה ל-`tapes.json`:**

| שדה | חובה | מה |
|---|---|---|
| `id` | ✓ | אותיות לועזיות קטנות, ספרות ומקף — מופיע בכתובת (`#/tape/<id>`) |
| `title` | ✓ | הכותרת על הקופסה |
| `src` | ✓ | כתובת ה-Release המלאה (`https://github.com/.../releases/download/...`) |
| `subtitle` | | שורה קטנה מתחת לכותרת |
| `shelf` | | שם המדף (ברירת מחדל: "הסרטונים שלי") |
| `colour` | | צבע הקופסה, `#RRGGBB` — כדאי אותו צבע כמו שדרת הספר |
| `duration` | | אורך בשניות, מ-`chapters.py` |
| `chapters` | | `[{ "t": שניות, "title": "..." }]`, מ-`chapters.py` |
| `new` | | `true` מדביק מדבקת "חדש!" |
| `book` | | ה-`id` של הספר בספרייה — ההערה לצופים מתחת לנגן מקשרת אליו ("המקור המדויק הוא הספר") |

כותרות בצורת `פרק 4 · ...` ממוספרות לפי המספר שבכותרת (מקש `4` קופץ
ל"פרק 4" ולא לשורה הרביעית ברשימה). כותרת בצורת מילה + אות עברית + `·`
(`חלק ב · ...`, `שער ב · ...`, `קו ב · ...` — כל ספר קורא לחלקים אחרת) מוצגת
ככותרת ביניים.

### ⚠️ למה הסרטונים ב-Release ולא במאגר

- GitHub **חוסם** כל קובץ מעל 100MB בדחיפה. Git LFS אינו פתרון: Netlify
  הפסיקה לתמוך בו (Large Media) ב-2023, והאתר היה מקבל קובצי מצביע.
- קובץ ב-Release לא נכנס להיסטוריה של git ולא נספר במכסת התעבורה של
  Netlify. עד 2GB לקובץ.
- **המאגר חייב להיות ציבורי.** קובץ ב-Release של מאגר פרטי מחזיר 404 לכל
  מי שאינו מחובר ל-GitHub — כלומר לכל מבקר באתר.
- `media-src` ב-`_headers` מתיר את `github.com` **וגם** את
  `release-assets.githubusercontent.com`: הכתובת מחזירה 302 לכתובת חתומה
  שם, ו-CSP בודק גם את יעד ההפניה.
- ⚠️ **הכתובת החתומה פגה אחרי 5 דקות** (נמדד), והדפדפן ממשיך להשתמש בה
  (נמדד: 4 הפניות מול 20 בקשות). בלי טיפול, כל קפיצה אחרי 5 דקות צפייה
  נכשלת. `Player.recover()` ב-`videos.js` מבקש הפניה טרייה וחוזר לאותה
  נקודה ולאותו מצב ניגון — וזה נבדק מול GitHub מדומה שמדמה את התפוגה
  (`tests/fakegithub.py`).

### ⚠️ אייפון: ממסר הווידאו (‏`/v/<קובץ>`)

GitHub מגיש את קובצי ה-Release כ-`application/octet-stream` עם
`Content-Disposition: attachment`, ומפנה לכתובת חתומה **בלי סיומת .mp4**
(והסוג חתום בתוך הכתובת — אי אפשר לבקש אחר). כרום במחשב מזהה MP4 לפי
התוכן ומתעלם; **באייפון כל הדפדפנים — גם כרום — הם WebKit**, שמסתמך על
הסוג המוצהר או על הסיומת, ולכן מסרב לנגן ("הקלטת נתקעה" כבר ב-0:00).

`netlify/edge-functions/video.js` מבקש את אותו קובץ מ-GitHub (כולל Range)
ומעביר אותו כ-`video/mp4`. **הוא גיבוי בלבד:** הנגן מנסה קודם ישירות
מ-GitHub, ועובר לממסר רק כשנכשל לפני שהסרטון נטען — וזוכר את זה לשאר הביקור
(`sessionStorage`, ‏`dl:video-proxy`). כל בייט שעובר דרך הממסר נספר במכסת
התעבורה של Netlify, ולכן מחשבים ואנדרואיד לא משתמשים בו. רק קבצים מה-Release
‏`videos-v1` של המאגר הזה — הוא לא ממסר כללי.

### מה נשמר בדפדפן

| מפתח | תוכן |
|---|---|
| `dl:tape:<id>:state` | המיקום בקלטת (נמחק כשהקלטת מסתיימת — "גולגלה") |
| `dl:video-settings` | עוצמת קול והשתקה |
| `dl:settings` → `theme` | מתג האור. ⚠️ **אותה הגדרה של המנורה בספרייה** — כיבוי כאן מכבה שם ולהפך, ושאר השדות של הספרייה נשמרים |

### קיצורי מקלדת בנגן

רווח/`K` ניגון והשהיה · `←`/`→` עשר שניות · `[`/`]` פרק קודם/הבא ·
`1`–`9` לפרק לפי מספרו · `C` רשימת הפרקים · `F` מסך מלא · `M` השתקה ·
`Esc` הוצאת הקלטת. המקור היחיד הוא `SHORTCUTS` ב-`videos.js`, וממנו
נבנית גם חלונית הקיצורים.

## ✦ קריאה בלי אינטרנט (לטיסה)

הספרים — לא הסרטונים — אפשר לשמור במכשיר ולקרוא בלי שום חיבור.

- **איך שומרים:** בכרטיס של כל ספר יש כפתור "שמירה לקריאה בלי אינטרנט",
  ובכותרת יש כפתור "קריאה בלי אינטרנט" שפותח רשימה של כל הספרים עם
  "שמירת כל הספרים" (כ-10MB). ספר שמור מסומן על המדף בחותם פליז קטן.
- **מה עובד בלי חיבור:** המדף, פתיחת ספר שמור ודפדוף בו, תוכן העניינים,
  החיפוש, הסימניות והפנקס (ההערות נשמרות במכשיר בכל מקרה). ספר שלא נשמר
  מציג הסבר במקום שגיאה, ואוסף הקלטות מודיע שהוא זמין רק עם אינטרנט.
- **⚠️ אייפון ואייפד:** קודם "שיתוף" ← "הוסף למסך הבית", ואז לפתוח את
  הספרייה **מהאייקון** ולשמור משם. לאפליקציה שבמסך הבית יש אחסון נפרד
  מספארי, וספארי רגיל רשאי למחוק נתונים של אתר שלא ביקרו בו שבוע.
- **עדכון ספר:** ספר שמור שהוחלף בשרת (קובץ חדש באותו שם, או `rev` חדש)
  יורד מחדש לבד ברקע בפעם הבאה שהאתר נפתח עם חיבור.

איך זה בנוי:

| קובץ | תפקיד |
|---|---|
| `sw.js` | Service Worker. מגיש את האתר עצמו בלי רשת (רשת-קודם, עם גבול 4 שניות ל-Wi-Fi רעוע), ואת הספרים השמורים מהמטמון — כולל בקשות Range ש-PDF.js שולח. |
| `Offline` ב-`script.js` (§11ב) | הכפתורים, ההורדה עם התקדמות, הבדיקה שמה שנשמר הוא באמת PDF, הפס "אין חיבור". |
| `manifest.webmanifest`, `assets/icons/` | התקנה למסך הבית. האייקונים נוצרים מ-`favicon.svg` ב-`tools/icons.py`. |

- המטמון `dl-books` לעולם לא נמחק בעדכון של `sw.js`. מעטפת האתר כן —
  כשמעלים את `VERSION` ב-`sw.js` (לא נחוץ בשינוי רגיל: היא רשת-קודם).
- ⚠️ ה-CSP: בקשות של Service Worker כפופות ל-`connect-src` של **הכותרות
  של `sw.js`**, ולכן `fonts.googleapis.com`/`fonts.gstatic.com` נוספו שם.
- לא עוברים דרך ה-SW בכלל: `/api/*`, `/v/*`, עמוד הסרטונים ו-`tapes.json`.

## ✦ מונה המבקרים

בפוטר של שני העמודים: לוחית פליז עם תופי ספרות בספרייה, ותצוגת LED אדומה
באוסף קלטות הוידאו.

- **ביקור = דפדפן אחד, בעמוד אחד, פעם ביום.** הדפדפן זוכר ב-`localStorage`
  (`dl:visits:<עמוד>`) את התאריך שבו כבר נספר; באותו יום הוא רק קורא את
  המספר. רענון ומעבר בין ספרים לא מנפחים את המונה.
- **איפה המספר נשמר:** האתר סטטי, ולכן יש כאן יוצא מן הכלל אחד — פונקציית
  Netlify (`netlify/functions/visits/`, בנתיב `/api/visits`) ששומרת מספר
  אחד לכל עמוד ב-Netlify Blobs. אותו origin, ולכן ה-CSP לא השתנה. זו גם
  הסיבה ל-`package.json` (תלות אחת, `@netlify/blobs`).
- **פרטיות:** נשמר רק המספר. בלי עוגיות, בלי IP ובלי מזהה.
- **נקודת ההתחלה** היא 349 לכל עמוד — `START` ב-`counter.mjs`. היא חלה רק
  כשעדיין אין ערך שמור; לשינוי אחרי שהמונה כבר רץ צריך למחוק את המפתח
  ב-Netlify (בממשק של הפרויקט, באזור Blobs, ב-store בשם `visits`).
- כשהבקשה נכשלת (שרת מקומי, חוסם פרסומות, אין רשת) המונה פשוט לא מופיע.
- ⚠️ קריאה-ועדכון אינם אטומיים: שני ביקורים באותה מילישנייה עלולים להיספר
  כאחד. באתר אישי זה זניח.

## ✦ פרסום ב-Netlify

חיבור חד-פעמי:

1. היכנסו ל-[app.netlify.com](https://app.netlify.com) → **Add new site** → **Import an existing project**.
2. בחרו GitHub ואת המאגר `DanTouitou91/Dans-Library`.
3. הגדרות הבנייה — **השאירו ריק**:
   - Build command: *(ריק)*
   - Publish directory: `.`

   `netlify.toml` כבר מגדיר את זה, אז אפשר פשוט ללחוץ Deploy.
4. לאחר הפרסום הראשון אפשר לשנות את שם הדומיין תחת **Site settings → Domain management**.

מכאן כל `git push` מפרסם אוטומטית.

### למה הספריות שמורות בתוך המאגר ולא נטענות מ-CDN

- ה-**worker** של PDF.js חייב להיות באותו origin כמו האתר. טעינה מ-CDN מחייבת
  עקיפה דרך blob ומסבכת את מדיניות האבטחה.
- PDF.js קורס אם גרסת הספרייה וגרסת ה-worker אינן זהות. שני קבצים נעולים
  ב-git לעולם לא יתפצלו זה מזה.
- האתר ממשיך לעבוד גם אם ה-CDN נופל.

## ✦ מנורת הספרייה

מתג הבהיר/כהה הוא מנורת ספרייה מצוירת (SVG) שעומדת בראש הדף, וגרסה
קטנה שלה יושבת גם בסרגל הקריאה. היא מקור האור של האתר:
**דולקת = תצוגה בהירה, כבויה = תצוגה כהה.** המצב נשמר בדפדפן.

כל התאורה נשענת על משתנה אחד, `--lamp` (0 או 1), שנקבע מ-`data-lamp`
שעל `<html>`. ההדלקה מבהבת קצרות כמו חוט להט שמתחמם, והכיבוי משאיר
זוהר שארית קצר. שתי האנימציות מכובות אוטומטית עבור מי שהגדיר
`prefers-reduced-motion`.

### שלוש הגדרות שנראות טכניות אבל קריטיות

**1. גרסת PDF.js — 5.4.624, ולא 3.x**
גרסה 3.11.174 מציגה את ספרי העברית **עם רווחים בתוך המילים**. זה נבדק על
ספר אמיתי: אותו קובץ בדיוק נראה מושלם בכל מציג אחר ושבור ב-3.x.
משתמשים ב-build ה-**legacy**, שכולל polyfill ל-`Promise.withResolvers`
ולכן עובד גם ב-Safari מתחת ל-17.4 וב-Firefox מתחת ל-121.

**2. `disableFontFace: true` ב-`script.js`**
כברירת מחדל PDF.js מזריק את הגופנים של ה-PDF כ-`@font-face`. אם ההזרקה
נכשלת (מדיניות CSP, FontFaceSet חסום) הדפדפן מחליף בשקט לגופן אחר —
האותיות נראות נכון אבל הרווחים ביניהן שגויים. ההגדרה הזו מציירת כל אות
כנתיב וקטורי מתוך הגופן המוטמע. עלות: כ-5ms לעמוד.

**3. `'unsafe-inline'` ב-`style-src` שבקובץ `_headers`**
StPageFlip ממקם כל עלה דרך `element.style.cssText`, ו-CSP חוסם את זה בלי
ההיתר. **בלי השורה הזו הקורא נטען אבל נשאר ריק לגמרי** — ורק בסביבת
הייצור, כי שרת פיתוח מקומי לא שולח כותרות CSP. ההגנה החשובה נשמרת:
`script-src` הוא `'self'` בלבד.

אם בעתיד יתווסף ספר שנראה שבור, כדאי לבדוק את שלוש ההגדרות האלה קודם.

**4. אייקונים הם SVG ולא תווי טקסט**
תווי חצים מסוג סוגריים (`❰ ❱ ‹ ›`) נושאים את התכונה `Bidi_Mirrored`,
והדפדפן מצייר אותם **הפוך** בהקשר RTL. זה גרם לחצי הדפדוף להצביע
לכיוון ההפוך. לכל האייקונים יש `<symbol>` ב-`index.html`, ול-SVG אין
שום התנהגות דו-כיוונית. אל תחזירו גליפים כאלה ללחצני ניווט.

**5. ניווט במסך צר לא עובר דרך flipPrev**
בתצוגת פורטרט (מסך צר) StPageFlip מציג עלה אחד ומציב אותו בחצי הימני,
עם `setLeftPage(null)`. הפונקציה `flipPrev` מדמה מגע בנקודה `x=10` —
כלומר בחצי השמאלי — ושם פשוט אין עמוד, ולכן הקריאה לא עושה כלום.
**התוצאה הייתה שבמובייל אפשר היה רק לחזור אחורה, לא להתקדם.** לכן
`advance`/`retreat` בודקים `isPortrait()` ומנווטים לפי מספר עמוד.
אל תסירו את הבדיקה הזו.

**6. הכריכה היא ספר סגור**
עלה `data-blank="true"` הוא *היעדר עמוד*, לא עמוד ריק. הוא קיים רק בשני
קצות הספר ותפקידו לשמור על מבנה הכפולה, ולכן הוא שקוף לחלוטין — אחרת
הכריכה נראית כמו ספר פתוח על דף ריק. כשהכפולה מכילה רק את הכריכה,
`reconcile` מסמן `#flip-book.is-closed` והספר ממורכז.
ה-`transition` מוגדר על `.is-closed` ולא על `#flip-book`, ולכן הוא פועל
רק בסגירה: בפתיחה המרכוז יורד בפריים אחד, אחרת העמוד שנחשף נחתך
בקצה השמאלי למשך כ-150ms.

**7. העמוד נצבע על לבן, ואין שכבת "נייר" מתחתיו**
עמוד PDF כמעט אף פעם לא מצייר רקע משלו — הוא שקוף במקום שבו העיצוב
שלו לבן. לכן כל צבע שנצבע מתחתיו נראה כאילו הוא חלק מהעמוד. פעם צבענו
כאן `#F4E8D0` כדי לשמור על מראה וינטג', והתוצאה הייתה **שכל שוליים
לבנים בספרים יצאו חומים והמסגרת המעוצבת נעלמה**. יחד איתו הוסרו גם
הגרדיאנטים והוויניטה החומה (בעומק 58px) שהיו על `.leaf-inner`.
הספרים של דן מעוצבים בעצמם — האתר לא צובע אותם.

**8. רוחב הספר מוגבל לפי גובה הבמה (`fitToStage`)**
StPageFlip עם `autoSize` גוזר את גובה הספר **אך ורק מהרוחב**: הוא נותן
ל-wrapper ריפוד תחתון באחוזים לפי `height / (width*2)`. הגובה הזמין
בחלון לא משפיע עליו בכלל, ולכן בחלון רחב ונמוך תחתית העמוד נחתכה
ודרשה גלילה. `fitToStage()` מחשב את הרוחב המרבי שממנו נגזר גובה
שנכנס בבמה. אל תסירו אותו — בלעדיו העמוד לא מוצג במלואו.

**9. הכפולות בסדר הקריאה — ורק בתוכן הכפולה מחליפים צדדים**
זו הנקודה העדינה ביותר בקובץ. StPageFlip בנוי לספר לועזי, והפיתוי הוא
לשקף או להפוך את כל מערך העלים. **אל תעשו זאת.** הפיכת המערך אכן נותנת
מיקום נכון, אבל היא מכריחה את "קדימה" לקרוא ל-`flipPrev` — אנימציית
ה*חזרה* של הספרייה — והדף נסחף משמאל לימין, כלומר כמו דפדוף אחורה
בספר לועזי. נמדד על 16 פריימים רצופים: מרכז הדף המתהפך נע מ-‎-404
ל-974 בזמן שהקורא התקדם מעמוד 6 ל-8.

התובנה: **תנועת הדפדוף זהה בשתי השפות** — תמיד מרימים את הדף הימני
ומעיפים אותו שמאלה. מה שמבדיל ספר עברי הוא מספור העמודים בלבד. לכן
הכפולות נשמרות בסדר הקריאה, ורק שני העמודים שבתוך כל כפולה מוחלפים:
`[ריק,1] [3,2] [5,4] … [ריק,N]`. "קדימה" הוא `flipNext`, כרגיל.

**10. כישלון פתיחה מאובחן, ומנסים שוב פעם אחת**
`BookSource.openWithRetry` חוזר על הניסיון פעם אחת (חיבור סלולרי נופל
באמצע הורדה ו-PDF.js לא מנסה שוב מעצמו), ו-`BookSource.diagnose` בודק
מה באמת חזר מהשרת — 404, דף HTML, סוג תוכן אחר, או הורדה שנקטעה —
ומציג זאת. קודם כל תקלה שאינה 404 קיבלה את אותו משפט כללי.

**11. לעולם אל תוסיפו ספר לקטלוג לפני שהקובץ שלו עלה**
זה נראה לא מזיק, וזו הייתה התקלה החמורה ביותר כאן. הרשומה הופיעה
בקטלוג שעות לפני שהקובץ הועלה, וכל מי שלחץ על הספר בינתיים קיבל 404.
עד כאן סביר — אבל הכלל שהיה ב-`_headers` הוסיף לתשובה הזו
`Cache-Control: public, max-age=86400`. **Netlify מתאימה כללי כותרות
לפי הנתיב ולא לפי הסטטוס**, ולכן גם ה-404 נשמר במטמון ליממה שלמה:
הספר נשאר שבור אצל אותו משתמש גם אחרי שהקובץ עלה, ולשרת אין שום דרך
לבטל מטמון קיים.

שלוש הגנות הוטמעו:
1. `/books/*` הוא היום `max-age=0, must-revalidate`. היעילות נשמרת דרך
   ETag (תשובת 304 זעירה במקום 2MB), ושגיאה לא נשמרת יותר.
2. שדה `rev` ברשומת הספר מצורף לכתובת כ-`?v=…`. זו הדרך **היחידה**
   לעקוף עותק תקוע אצל משתמש — העלו אותו באחד כשמחליפים קובץ, או
   כשספר נשאר שבור אחרי שהקובץ כבר עלה.
3. חבילת הבדיקות מוודאת שכל `CATALOG[].file` באמת מחזיר 200 ו-PDF.

**12. אבחון חייב לשאול בדיוק כמו שהטעינה שואלת**
הגרסה הראשונה של `diagnose` שלחה כותרת `Range`. דפדפן עשוי לשרת בקשה
כזו מהרשת בזמן שבקשה רגילה מוגשת מעותק ישן שבמטמון — וכך התקבל אבחון
שאמר "הקובץ תקין בשרת" בזמן שהטעינה עצמה קיבלה 404 ישן. היום `diagnose`
מבקש בדיוק כמו PDF.js, ואם הבקשה הרגילה נכשלת אך `cache: 'reload'`
מצליחה הוא אומר זאת במפורש: מטמון ישן, ורענון מלא יפתור.

**13. לכל קובץ של האתר יש כלל מטמון מפורש — וזה קריטי**
שתי טעויות כאן גרמו למשתמש להריץ קוד ישן במשך ימים, בלי שום דרך לדעת:

1. **ל-`script.js` ול-`style.css` לא היה שום כלל.** בלי הנחיה מפורשת
   הדפדפן מחיל *מטמון היוריסטי* משלו — ספארי בנייד עושה זאת
   באגרסיביות — ולכן גרסאות חדשות פשוט לא הגיעו למכשיר.
2. **הכלל נכתב ל-`/index.html`, אבל נכנסים לכתובת `/`.** Netlify
   מתאימה כללים לפי נתיב הבקשה, ולכן הכלל לא חל על דף הבית כלל.

היום כל נתיב מפורט בנפרד ב-`_headers`, ו-`/vendor/*` הוא היחיד שנשמר
לשנה (הוא נעול לגרסה ולעולם לא משתנה). בנוסף, `index.html` טוען את
הקבצים עם `?v=` — זה נחוץ רק כדי לעקוף עותק תקוע שכבר שמור אצל משתמש,
והנכונות עצמה נשענת על הכותרות, ולכן אין חובה לעדכן אותו בכל שינוי.

⚠️ **שרת הבדיקות הסתיר את הבאג הזה.** הוא נירמל `/` ל-`/index.html`
לפני התאמת הכללים, וכך הכלל *נראה* כאילו הוא חל על דף הבית. זו הפעם
השלישית שפער בין סביבת הבדיקה לייצור הסתיר תקלה אמיתית (קודם: CSP,
ואחר כך בקשות Range). כל פער כזה נסגר מיד כשהוא מתגלה.

**14. תוכנית העלים תלויה באוריינטציה**
בתצוגת כפולה הכפולות בסדר הקריאה ורק שני העמודים שבתוכן מוחלפים
(סעיף 9). **בתצוגת עמוד בודד זה שגוי**: שם StPageFlip עוברת עלים לפי
סדר ה-DOM, ולכן אותה תוכנית נתנה את הסדר 1, 3, 2, 5, 4, ומעבר של צעד
אחד אחורה אפילו לא הצליח להתבצע. לכן `buildLeafPlan` מקבל `portrait`,
ובמסך צר מחזיר את סדר העמודים הטבעי. `rebuild()` בונה מחדש כשהמכשיר
מסתובב.

**15. מספר העמוד נגזר ממה שמוצג, ולא מוצהר מראש**
`goTo` עדכן את המונה מיד אחרי הבקשה לדפדף, בלי לוודא שהדף אכן זז. במסך
צר המספר התקדם בזמן שהעמוד נשאר במקומו — בדיוק מה שדן דיווח.
`_syncFromLibrary()` מיישר את המונה מול הכפולה שהספרייה באמת מציגה,
ונקרא כשהתנועה נעצרת (`changeState === 'read'`).
⚠️ אסור להפעיל אותו מיד אחרי הבקשה: הספרייה עוד לא עדכנה את האינדקס
שלה, והיישור דורס קפיצה מכוונת לעמוד. לכן יש השהיה ארוכה מזמן האנימציה.

⚠️ **ובדיקות: לעולם אל תאמתו ניווט לפי `Reader.currentPage()`.** זה
המספר שהקוד מדווח על עצמו, והוא עבר בהצלחה גם כשהעמוד לא זז כלל.
הבדיקות אומתו מחדש כך שהן קוראות את `data-page` של העלה שבאמת מוצג.

**16. כיוון הדפדוף מוגדר במקום אחד: `READING`**
זו הנקודה שגררה הכי הרבה סבבים, ולכן היא מרוכזת היום בקבוע אחד בראש
§8. שתי עובדות על StPageFlip, שנקראו מקוד הספרייה ולא שוערו:

| קריאה | מה היא מרימה | כיוון התנועה |
|---|---|---|
| `flipNext` | את הדף הימני | ימין ← שמאל |
| `flipPrev` | את הדף השמאלי | שמאל ← ימין |

**באתר הזה "קדימה" הוא `flipPrev`**, לבקשת דן: הכריכה נפתחת לכיוון ימין,
והחץ הימני הוא שמקדם. כדי ש-`flipPrev` יקדם את מספרי העמודים, הכפולות
נשמרות **בסדר הפוך לסדר הקריאה** — הכפולה האחרונה בספר היא הראשונה
במערך. בתוך כל כפולה העמוד הנמוך יושב מימין.

להיפוך כיוון ה*תנועה* יש לשנות את `READING`, ובעקבותיו את סדר הכפולות
ב-`buildLeafPlan`. ⚠️ שינוי אחד בלי השני מתקבל מצב חצי-הפוך, וזה בדיוק
מה שקרה כאן יותר מפעם אחת.

**מיקום הלחצנים הוא החלטה נפרדת ובלתי תלויה.** באתר הזה הדף נע
שמאלה→ימינה, אבל **החץ השמאלי הוא שמקדם** — כך ביקש דן, וזה תקף:
כיוון האנימציה וכיוון הכפתור אינם חייבים להתלכד. מה שכן חייב להתלכד
זה מיקום הלחצן, הסמל שעליו, סדר הלחצנים בסרגל ומקשי החצים —
`.page-nav--next/prev` ב-`style.css`, `#i-next`/`#i-prev` ב-`index.html`,
וה-`case` של המקלדת ב-§11.

**17. רמז השדרה בכריכה נמצא בצד שבו הספר נפתח**
הפס העדין לאורך קצה הכריכה מסמן את ציר הפתיחה. מכיוון שהספר נפתח
לכיוון ימין, בכריכה הקדמית הוא יושב בקצה **הימני**. העמוד האחרון הוא
סוף הספר ואינו נפתח משום מקום, ולכן הרמז שלו נשאר בקצה השמאלי —
ומכאן שהכלל ב-`style.css` מכוון ל-`[data-page="1"]` בלבד.

**18. הבמה אינה גוללת אלא כשבאמת צריך (`syncPan`)**
`.stage` הייתה `overflow: auto` תמיד. בזמן דפדוף הדף המסתובב חורג
ממנה — נמדד עד 736px לרוחב ו-663px לגובה, ב-17 מתוך 49 פריימים —
ולכן פסי גלילה הבזיקו למטה ובצד באמצע האנימציה, והפריסה קפצה איתם.

היום הגלילה נפתחת רק לפי הצורך:

| מצב | גלילה | פס |
|---|---|---|
| ספר, בלי זום | אין | — |
| ספר, בזום | יש (גרירה) | מוסתר |
| תצוגת גלילה | יש | **נשאר** — שם הוא מחוון מיקום לגיטימי |

⚠️ **`scrollWidth` אינו מדד לקיום פס גלילה**: הוא מדווח על היקף התוכן
גם כש-`overflow: hidden`. בדיקה שהסתמכה עליו נכשלה למרות שהתיקון עבד.
המדד הנכון הוא `offsetWidth - clientWidth`, כלומר העובי שהפס תופס.

**19. פסי גלילה — שני תחבירים, ואין ביניהם חפיפה**
איפה שפס גלילה כן מופיע (תצוגת גלילה, רשימת החיפוש, הפנקס והמדף) הוא
מעוצב בפליז על רקע עץ, ומתחלף עם מצב התאורה. צריך **שניהם**:
`scrollbar-width` / `scrollbar-color` הם התקן (Firefox, Chrome 121+,
Safari 18.2+), ו-`::-webkit-scrollbar` הוא הגיבוי ל-WebKit ישן.
⚠️ כשמוגדר `scrollbar-color`, דפדפני Blink מתעלמים מכללי
`::-webkit-scrollbar` — ולכן אלה גיבוי ולא כפילות, ואין ביניהם התנגשות.

⚠️ **אי אפשר לאמת את זה בפיקסלים בסביבת הבדיקה.** כרומיום ללא ראש אינו
מצייר פסי גלילה כלל — נבדק בעמוד בדיקה נפרד, גם עם המאפיינים התקניים
וגם עם `::-webkit-scrollbar`, ושניהם החזירו רוחב 0. הבדיקות מאמתות את
הערכים המחושבים ואת קיום כללי הגיבוי, לא את הציור.

**20. תווית שם הספר נדלקת על `pointerenter`, לא על `mouseenter`**
ריחוף על שדרה במדף מציג אחרי שנייה תווית עם שם הספר. בנייד הקשה על
אלמנט מייצרת גם `mouseenter` מדומה — ותווית שנדלקת ממגע נשארת תקועה
על המסך אחרי שהעמוד כבר התחלף לכרטיסיית הספר. לכן הבדיקה היא
`e.pointerType !== 'mouse'`.

התווית היא **אלמנט יחיד משותף** לכל השדרות ולא אחת לכל ספר, והיא
`position: fixed` עם מיקום מחושב ב-JS: שורת הספרים עלולה לגלול, ותווית
`absolute` בתוכה הייתה נחתכת. היא מסומנת `aria-hidden="true"` כי לשדרה
כבר יש `aria-label` עם אותו שם, ובלעדיו קורא מסך היה מקריא את הכותרת
פעמיים. בפוקוס מקלדת אין השהיה — מי שהגיע בטאב כבר בחר להתעכב.

**21. תוכן העניינים נקרא מהקובץ, והיעדים נפתרים אחד-אחד**
כל ארבעת הספרים נושאים עץ ניווט מוטבע (210 ערכים בגדול שבהם), אבל
היעדים שמורים כהפניות פנימיות ולא כמספרי עמוד. כל ערך נפתר דרך
`getDestination` ואז `getPageIndex`, פעם אחת, ונשמר במטמון.

⚠️ **הרווח בין מספר הפרק לשמו חסר בקובץ עצמו** — `"01 · פרק ראשוןמהי
מדיניות ציבורית"`. אין שם תו שורה לשחזר, נבדק. `tidyTitle` מתקן רק את
התבנית הזו, עם lookahead שדורש אות עברית צמודה: כותרת שכבר מרווחת נכון
לא תתאים לו לעולם, ולכן הוא אינו יכול לשבור כותרת תקינה. **אין כאן ניסיון
לנחש גבולות מילים בעברית**, ואין להרחיב את הכלל לכיוון הזה.

⚠️ **`_tocDrawn` נקבע רק אחרי ציור שהצליח.** סימון אופטימי לפני הציור
השאיר את הפאנל ריק לתמיד כשהציור נקטע — למשל כשהפאנל נפתח בזמן שהספר
עוד נטען. אותה משפחת באגים כמו מונה העמודים שדיווח על עצמו.

⚠️ **מעבר בין ספרים כשהפאנל פתוח.** תוכן העניינים והסימניות מצוירים
ברגע *פתיחת* הפאנל, ולכן מעבר לספר אחר בלי לסגור אותו השאיר את שניהם על
נתוני הספר הקודם. `open()` מרענן את שניהם כשהפאנל כבר פתוח.

**22. התווית ממוקמת פעמיים, כי השדרה זזה תחתיה**
התווית מופיעה מיד בריחוף, אבל השדרה עצמה נעה 0.28 שניות
(`translateY(-16px)` ועוד סיבוב קל). מדידה ברגע הריחוף תופסת אותה באמצע
התנועה, והתווית נוחתת על הספר במקום מעליו. לכן `placeTip` נקרא שוב
ב-`transitionend`, עם גיבוי ב-`setTimeout` כי ב-`prefers-reduced-motion`
אין מעבר ולכן גם אין אירוע. כל עוד הייתה השהיה של שנייה הבאג היה מוסתר.

**23. הייצוא ל-Word כותב `.docx` אמיתי, בלי ספרייה**
`docx` הוא ארכיון ZIP ובו XML. אין כאן ספריית zip ו-CSP חוסם CDN, ולכן
`Docx` כותב את הארכיון בעצמו בשיטת store (בלי דחיסה — טקסט הערות הוא
קילובייטים בודדים, וזה חוסך מימוש deflate שלם).

שלוש מלכודות שעלו רק מול קוראים אמיתיים, ולא מול בדיקה עצמית:
1. **`xmlns:r` חייב להיות מוכרז** על `w:document` גם כשאין במסמך אף
   הפניה. קוראים ניגשים ל-`nsmap['r']` בלי לבדוק, ונופלים בלעדיו.
2. **סדר הילדים ב-`w:pPr` קבוע בסכמה**: `bidi` לפני `spacing` לפני `jc`.
3. **`word/_rels/document.xml.rels` חייב להתקיים** גם כשהוא ריק.

⚠️ הכול דו-כיווני במפורש — `w:bidi` בפסקה, `w:rtl` בריצה ו-`w:bidi`
ב-`sectPr`. בלעדיהם Word פותח מסמך עברי מיושר לשמאל.

⚠️ **זה ייצוא ולא גיבוי.** אין דרך לטעון את הקובץ בחזרה לאתר; ההערות
עצמן ממשיכות לחיות ב-localStorage בלבד.

**24. `goTo` חייב להימנע מ-`flip()` במסך צר**
StPageFlip במצב פורטרט לא מזיז את עצמו כשקוראים ל-`flip(idx)` — האינדקס
הפנימי נשאר תקוע והעמוד לא מתחלף. `turnToPage(idx)` עובד תמיד.

זו אותה מלכודת שבגללה `advance`/`retreat` כבר עוברים דרך `_stepByIndex`,
אבל `goTo` לא קיבל את הטיפול — ולכן **כל** קפיצה בנייד הייתה שבורה:
תוכן עניינים, תיבת מספר העמוד, תוצאות חיפוש וסימניות כאחד. נמדד: מעמוד 5
בספר בן 111 עמודים נכשלו 6 מתוך 7 קפיצות, בעוד `turnToPage` הצליח בכולן.

⚠️ שים לב ש**גם המונה דיווח נכון** על העמוד הישן, ולכן באג כזה אינו
מתגלה בבדיקה שמסתמכת על `Reader.currentPage()`. יש לאמת מול
`data-page` של העלה שבאמת מצויר.

**25. פריסת הפאנלים בנייד — שלושה תיקונים נפרדים**
- **`100dvh` על `.view--reader`**: אלמנט `position: fixed` נמדד בנייד מול
  החלון ה"גדול", זה שכולל את השטח שמאחורי שורת הכתובת. תחתית התוכן
  נחתכה מאחורי כרום הדפדפן ולא הייתה דרך לגלול אליה. בדסקטופ `dvh`
  שווה ל-`vh` ואין שינוי.
- **`--toolbar-real-h`**: הסרגל נשבר לשתי שורות בנייד ותופס 85px, בעוד
  `--toolbar-h` הוא `clamp(56px, 8vh, 68px)`. הפאנלים נפתחו מתחת לערך
  הקבוע וראשם נחבא מאחורי הסרגל. הגובה נמדד עכשיו ב-ResizeObserver.
  ⚠️ **הערך נכתב למשתנה נפרד בכוונה.** ל-`.toolbar` יש
  `min-block-size: var(--toolbar-h)`, וכתיבה חזרה לאותו משתנה הייתה
  יוצרת גִּרְעוֹן: הגובה שנמדד פעם אחת היה הופך לרצפה, והסרגל לא היה
  מצליח להתכווץ בסיבוב המכשיר.
- **הפנקס נפתח מתחת לסרגל**, ולא מעליו. קודם הוא כיסה את הסרגל כולו,
  ולכן בנייד לא הייתה דרך לעבור ממנו לחיפוש בלי לסגור אותו קודם.

**26. פאנל אחד פתוח בכל רגע**
הפנקס ופאנל החיפוש יחד מכסים כמעט את כל המסך בנייד ולא נשאר מה לקרוא.
`toggleNotes(true)` סוגר את החיפוש ולהפך. ⚠️ השמירה מפני רקורסיה היא
שהקריאה ההדדית מותנית ב-`show` בלבד: סגירה לעולם אינה מפעילה סגירה.

**27. גלילה נבדקת בתנועה בלבד**
ל-`.finder` היה `overflow-y: auto` ומיד אחריו, באותו בלוק,
`overflow: hidden`. הקיצור המאוחר מאפס גם את `overflow-y`, והפאנל הפסיק
להיגלל באצבע ובגלגלת.

⚠️ **`overflow: hidden` עדיין מאפשר `scrollTop` מתוך קוד.** הבדיקה
שהציבה `scrollTop` עברה בזמן שהמשתמש היה תקוע — כלומר אימתה את מה
שהדפדפן מוכן לעשות עבור הסקריפט, לא את מה שאדם יכול לעשות. כל בדיקת
גלילה עוברת דרך `mouse.wheel`.

**28. שני טוקנים ייעודיים לטקסט: `--brass-text` ו-`--accent-text`**
`--brass` ו-`--burgundy` משמשים גם למסגרות, לפסי גלילה ולשדרות, ושם
הגוון הכהה תקין. כטקסט הם נכשלו: `--burgundy` על `--paper` במצב חשוך
נתן **1.16:1**, ו-`--brass` על עץ נתן 3.01:1. ההפרדה מתקנת את הטקסט
בלי לשנות את מה שלא צריך.

⚠️ גם `.pagebox__total` נשען על `--paper`, שמתהפך עם המנורה — אבל
הסרגל הוא עץ כהה **בשתי** הערכות, ולכן התקבל כהה על כהה.
טקסט שיושב על משטח קבוע חייב צבע קבוע.

⚠️ **ניגודיות נמדדת מפיקסלים.** `getComputedStyle` קורא רק
`backgroundColor`; על `.btn--wood`, שרקעו `linear-gradient`, הוא "רואה"
את המשטח שמאחורי הלחצן ומדווח 1.01:1 על לחצן תקין לגמרי. שתי שיטות
מדידה נפסלו בדרך — גם "רבעון הפיקסלים הרחוקים", שעל אלמנט שרובו רקע
דיגם בעיקר רקע והחזיר 1.17:1 על טקסט קריא.

**29. `.btn--brass` שקוף למחצה — רק על עץ כהה**
זו הסיבה שלחצן הייצוא ל-Word היה **1.19:1**: הוא היחיד שישב על הנייר
הבהיר של הפנקס, והרקע הבצבץ מבעדו. `.btn--wood` אטום ולכן אינו תלוי
במשטח. לפני שמוסיפים לחצן, יש לשאול על מה הוא יושב.

**30. עמעום הדף בלילה — המסנן על הקנבס בלבד**
⚠️ `filter` יוצר containing block ושובר `transform-style: preserve-3d`.
על `.leaf` הוא היה הורס את אנימציית הדפדוף. ה-`canvas` הוא עלה סופי
ואינו נושא טרנספורם, ולכן בטוח. הרקע הלבן של `.leaf`/`.leaf-inner`
מעומעם בנפרד, אחרת נשארת מסגרת בוהקת סביב דף כהה, וההדגשות מותאמות
כי הן מצוירות *מעל* הקנבס ואינן עוברות את המסנן.

**31. קורא→קורא בין שני ספרים**
`Router.apply` סגר את הקורא רק ביציאה ממנו. מעבר ישיר מספר לספר — אפשרי
עם כפתור "אחורה" — נפל ל-`open()` בלי `close()`: `flushNotes` לא רץ,
עד חמש שניות של כתיבה נמחקו, וה-PDF הישן לא שוחרר.

**32. Esc סוגר שכבה, ולא מנווט**
`Router.back('#/')` רץ על **כל** שכבה, ולכן חלונית שנפתחה מתוך הקורא
הייתה נסגרת ב-Esc **וגם** זורקת את הקורא חזרה למדף. היום רק כרטיס
הקטלוג מנווט, בדיוק כמו בנתיב הלחיצה.

**33. קיצורי המקלדת הם מקור אמת אחד**
`SHORTCUTS` היא גם טבלת השיגור של מטפל המקשים וגם מה שמוצג בחלונית,
ולכן חלונית שמראה קיצור שאינו עובד היא בלתי אפשרית. יש בדיקה שמפעילה
כל קיצור שמוצג ומוודאת שמשהו באמת קרה.

**34. Google Analytics — הקוד המוטבע חייב להיות בקובץ**
`script-src` הוא `'self'` בלי `'unsafe-inline'` (רק ל-`style-src` יש,
בשביל StPageFlip). הבלוק המוטבע שגוגל מספקת היה נחסם בשקט — בלי שגיאה
גלויה ובלי נתונים. הוא יושב ב-`assets/analytics.js`, ו-`script-src`
נשאר בלי `unsafe-inline`: ההיתר הזה היה פותח את האתר להזרקת קוד.

### על כיווניות (RTL) בעריכה עתידית

הדפדפן מהפך לבד מאפיינים לוגיים (`inset-inline`, `margin-inline`), אבל
**לא** מהפך את אלה, והם תמיד פיזיים:

`transform` / `translateX` · `box-shadow` (היסט אופקי) · `transform-origin`
· `linear-gradient(to left|right)` · `border-radius` (פינות) ·
`background-position` · `clip-path`

כל באג ה-RTL שהיה בקובץ ישב באחד מהם — וגם באג כיוון הדפדוף
(סעיף 9), שלא ישב ב-CSS כלל אלא בסדר שבו הוזנו העלים. בכל מקום כזה בקוד יש היום הערה
שמסבירה לאיזה צד הוא מכוון ולמה.

## ✦ קיצורי מקלדת בקורא

בקורא יש לחצן מקלדת שפותח חלונית עם הרשימה המלאה (מוסתר בנייד — קיצורי
מקלדת חסרי משמעות במסך מגע).

⚠️ **מקור האמת הוא `SHORTCUTS` ב-`script.js`**, שהוא גם טבלת השיגור של
מטפל המקשים וגם מה שמוצג בחלונית. הטבלה כאן היא עותק לנוחות הקריאה —
אם היא נסתרת מהקוד, הקוד צודק. אין להוסיף קיצור בלי להוסיף אותו שם.

| מקש | פעולה |
|---|---|
| `←` | העמוד הבא |
| `→` | העמוד הקודם |
| `רווח` | העמוד הבא · `Shift+רווח` הקודם |
| `Home` / `End` | תחילת הספר / סופו |
| `ב` או `b` | סימניה בעמוד הנוכחי |
| `ח` או `f` | חיפוש וסימניות |
| `מ` או `n` | פתיחת פנקס המלומד |
| `Esc` | יציאה שכבה אחת אחורה |

## ✦ מה נשמר בדפדפן

הכל נשמר מקומית בלבד (`localStorage`) — שום מידע לא נשלח לשום שרת.

| מפתח | תוכן |
|---|---|
| `dl:settings` | מצב בהיר/כהה, סוג התצוגה, רמת הזום |
| `dl:book:<id>:state` | העמוד האחרון שנקרא |
| `dl:book:<id>:notes` | תוכן פנקס המלומד |
| `dl:book:<id>:marks` | רשימת העמודים המסומנים |

ההערות נשמרות אוטומטית תוך פחות משנייה, וגם ביציאה פתאומית מהדף.
אם נגמר המקום בדפדפן, המערכת מוחקת קודם נתונים שניתן לשחזר —
**הערות וסימניות לעולם לא נמחקות אוטומטית.**

## ✦ חיפוש וסימניות

לחצן הזכוכית המגדלת בסרגל (או `ח`) פותח פאנל אחד שמשרת שתי מטרות:
תיבת החיפוש למעלה, ומתחתיה **רשימת הסימניות** כשאין חיפוש פעיל.
לחיצה על תוצאה או על סימנייה קופצת לעמוד, ו-`×` מסיר סימנייה.

**החיפוש עובד על הטקסט האמיתי של ה-PDF**, לא על שמות הקבצים: בפעם
הראשונה שמחפשים בספר, הטקסט של כל עמוד מחולץ דרך `getTextContent`
של PDF.js. בספר בן 111 עמודים זה לוקח פחות משנייה, ומוצג מחוון
התקדמות. ההשוואה מתעלמת מניקוד, מרישיות ומתווי כיווניות, כדי
שחיפוש בעברית יתנהג כמצופה.

**התוצאה מסומנת גם על הדף עצמו.** לחיצה על תוצאה לא רק קופצת לעמוד
אלא צובעת את המופעים בו בכתם ענבר. המיקומים מגיעים מ-`getTextContent`,
וממופים לקואורדינטות התצוגה דרך
`PDFJS.Util.transform(viewport.transform, item.transform)` — ולכן הם
נשארים מדויקים בכל רמת זום ובכל גודל מסך. מעבר מסימנייה אינו חיפוש
ולכן אינו מדליק הדגשה.

⚠️ **`paintHighlights` חייב לסנן לעלים הנראים בלבד.** StPageFlip משאיר
את כל העלים ב-DOM עם `display: none`, ועלה מוסתר מחזיר
`getBoundingClientRect` אפס — כך שהתיבות יצאו `NaN`. מעבר על כולם גם
היה מריץ חילוץ טקסט מ-111 עמודים בכל דפדוף.

**תוכן העניינים** יושב באותו פאנל, מתחת לסימניות. הוא נבנה מעץ הניווט
המוטבע בקובץ: רשימת הפרקים פרושה, והסעיפים שתחת כל פרק נפתחים בלחיצה על
החץ. 210 ערכים הם יותר מדי לפרישה מלאה, ולכן ברירת המחדל היא צלילה
פנימה ולא מגילה ארוכה.

⚠️ **האינדקס נשמר בזיכרון בלבד ולעולם לא ב-localStorage.** ספר בן 111
עמודים הוא כמה מאות אלפי תווים; שמירה שלו הייתה גודשת את מכסת הדפדפן
ומסכנת את מה שיקר באמת — ההערות והסימניות. המחיר הוא חילוץ מחדש אחרי
רענון, והוא זניח.

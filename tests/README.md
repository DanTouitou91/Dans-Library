# חבילת הבדיקות

260+ בדיקות שמריצות את האתר האמיתי בכרומיום. הן לא בודקות שהקוד מדווח
שהוא עובד — הן בודקות מה באמת מצויר על המסך.

## הרצה

```bash
pip install playwright pillow python-docx imageio-ffmpeg
python3 -m playwright install chromium

python3 tests/cspserve.py &          # מ-שורש המאגר
python3 tests/verify.py              # 180 בדיקות זרימה בספרייה
python3 tests/csp_check.py           # CSP ורינדור, בארבעת הספרים
python3 tests/videos_check.py        # אוסף קלטות הוידאו של דן (מפעיל לבד את fakegithub.py)
python3 tests/visits_check.py        # מונה המבקרים בדפדפן (‏/api/visits מדומה)
node --test tests/visits_test.mjs    # לוגיקת פונקציית המונה, עם store בזיכרון
```

⚠️ השרת המקומי לא מריץ פונקציות של Netlify, ולכן בשאר הבדיקות ‏`/api/visits`
מחזיר שגיאה והמונה פשוט לא מופיע — זו ההתנהגות הנכונה, לא תקלה.

## הנגן: GitHub מדומה (`fakegithub.py`)

הסרטונים יושבים ב-GitHub Releases, ושם שלושה דברים שהבדיקות חייבות לראות
כמו במציאות: הפניית 302 לכתובת חתומה, CSP שבודק גם את יעד ההפניה, ו**כתובת
חתומה שפגה אחרי 5 דקות**. `page.route` של playwright לא מתאים: בקשה שנוצרת
מהפניה שמולאה ב-route יוצאת לרשת האמיתית בלי יירוט. לכן `videos_check.py`
מרים שרת HTTPS מקומי ומפנה אליו את הדומיינים של GitHub
(`--host-resolver-rules`). משך החיים של הכתובת והקצב נשלטים במשתני סביבה,
כך שהבדיקה של "הכתובת פגה באמצע קפיצה לפרק" לוקחת שניות ולא 5 דקות.

- ⚠️ **קובץ הבדיקה הוא VP9/Opus ולא H.264.** כרומיום של playwright נבנה
  בלי קודקים מוגנים ולא מנגן H.264. הסרטונים האמיתיים יכולים להיות H.264.
- ⚠️ **בדיקת התפוגה חייבת להוכיח שהתפוגה קרתה.** קובץ של 140KB נטען כולו
  בבקשה אחת, ואז שום בקשה לא נשלחת אחרי שהכתובת פגה — והבדיקה "עוברת"
  בלי לבדוק כלום. לכן השרת מגביל קצב (`FAKEGH_CHUNK`, `FAKEGH_DELAY`),
  והבדיקה דורשת לפחות תשובת `expired` אחת ביומן.

## ⚠️ למה `cspserve.py` ולא `python -m http.server`

זו לא נוחות. שלושה באגים הגיעו לייצור **דווקא** מפני שהשרת המקומי היה
סלחני יותר מ-Netlify, וכל אחד מהם נתפס רק אחרי שהשרת כאן הפסיק לרמות:

1. **הוא מגיש את `_headers` כלשונו.** ה-CSP של הייצור חוסם דברים
   ששרת רגיל מתיר — למשל סקריפט חיצוני או בלוק מוטבע. בלי זה הבדיקה
   עוברת והאתר נשבר אצל המשתמש, בלי שום שגיאה גלויה.
2. **הוא תומך ב-Range.** ‏PDF.js טוען ספר בן 111 עמודים במנות; שרת בלי
   Range מסתיר בעיות טעינה שלמות.
3. **הוא לא מנרמל `/` ל-`/index.html`.** ‏Netlify מתאימה כותרות לפי
   נתיב הבקשה, ולכן כלל שמוגדר ל-`/index.html` **אינו** חל על דף
   הבית. שרת שמנרמל הסתיר את זה, ומשתמשים קיבלו קוד ישן מהמטמון.

## מה נשמר כאן

לכל בדיקה כמעט יש באג אמיתי מאחוריה, והערות ⚠️ בקוד מסבירות אילו.
הבולטות:

- **המונה משקר.** אחרי קפיצה מספר העמוד התעדכן בזמן שהדף לא זז. כל
  בדיקת ניווט מאמתת את `data-page` של העלה שבאמת מצויר.
- **גלילה נבדקת בתנועה.** ל-`.finder` היה `overflow-y:auto` ואחריו
  `overflow:hidden` באותו בלוק. הפאנל הפסיק להיגלל באצבע — אבל
  `scrollTop` מתוך קוד המשיך לעבוד, ולכן הבדיקה עברה בזמן שהמשתמש היה
  תקוע. גלילה נבדקת רק ב-`mouse.wheel`.
- **ניגודיות נמדדת מפיקסלים.** ‏`getComputedStyle` קורא רק
  `backgroundColor`, ולכן על לחצן עם גרדיאנט הוא מדווח 1.01:1 על לחצן
  תקין. הרקע נדגם מהפיקסלים שצוירו.
- **404 נשמר במטמון.** ספר שהופיע בקטלוג לפני שהקובץ עלה נשמר ליממה
  אצל המשתמש. יש בדיקה שכל ספר בקטלוג באמת קיים.
